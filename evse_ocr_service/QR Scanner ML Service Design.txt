End-to-End Machine Learning Architecture for Degraded EVSE ID Recognition and Recovery
Executive Summary and Problem Formulation
The global proliferation of Electric Vehicle (EV) charging infrastructure has introduced distinct operational challenges at the intersection of hardware maintenance, physical environments, and digital user experiences. A critical node in the user journey occurs at the initialization of a charging session, frequently facilitated by scanning a physical QR code affixed to the Electric Vehicle Supply Equipment (EVSE). These optical markers encode essential routing metadata, primarily the standardized EVSE ID, which mobile applications utilize to locate the precise digital asset in the backend system, authenticate the user, and initiate power delivery.
However, hardware deployed in outdoor environments is subject to continuous environmental degradation. QR stickers routinely experience severe ultraviolet (UV) fading, material weathering, and vandalism. Concurrently, mobile client constraints—such as inadequate camera focal adjustment, motion blur, and poor ambient lighting—frequently result in failed QR code localizations and decodings. When the deterministic QR component fails, the human-readable text surrounding the code, which explicitly states the EVSE ID, becomes the critical fallback mechanism.
This report details the architectural design, codebase implementation, and theoretical foundations of a comprehensive machine learning service engineered to solve this exact failure mode. The proposed system captures failed or degraded scan attempts from the mobile client, securely structures the telemetry and image data, and utilizes this corpus to continuously train and fine-tune a Transformer-based Optical Character Recognition (TrOCR) model. By transitioning from deterministic QR decoding to probabilistic, vision-language model-based text extraction, the system can dynamically recover alphanumeric identifiers from heavily degraded images.
The architecture is divided into four interdependent components. First, a highly concurrent Data Ingestion API captures high-fidelity telemetry alongside the raw image buffer. Second, a bifurcated database architecture separates relational metadata from unstructured binary storage. Third, the model implementation leverages Microsoft's TrOCR, a vision-encoder/text-decoder architecture that excels in interpreting noisy, real-world text by applying implicit language modeling to visual features. Finally, an automated Machine Learning Operations (MLOps) pipeline automatically applies synthetic degradation to successful scans, fine-tunes the model, and strictly validates outputs against ISO 15118 and DIN SPEC 91286 regulatory standards.
Data Ingestion Layer and API Architecture
To construct a robust dataset capable of training a neural network to recognize degraded text, the application requires a centralized ingestion service. The API must be designed to accept multipart payloads containing both the raw binary image frame from the mobile device and a structured JSON payload detailing the environmental context of the scan failure.
Payload Specification and Contextual Telemetry
The ingestion endpoint must capture variables that contribute to optical failures. Recording ambient light levels helps the system understand failure distributions between overexposed daylight conditions and underexposed night conditions. Geospatial coordinates serve a dual purpose: providing an approximate location to filter candidate EVSE IDs and cross-referencing the physical hardware's known location in the primary charging station database.

@app.post("/api/v1/telemetry/failed_scans")
async def ingest_failed_scan(
   background_tasks: BackgroundTasks,
   image_payload: UploadFile = File(...),
   telemetry_data: str = Form(...)
):
   """
   Ingests failed QR scan attempts from the mobile client.
   """
   # Validate the MIME type to prevent malicious uploads
   allowed_formats = {"image/jpeg", "image/png", "image/heic"}
   if image_payload.content_type not in allowed_formats:
       raise HTTPException(status_code=415, detail="Unsupported Media Type.")
   
   # Deserialize and validate the JSON telemetry using Pydantic
   try:
       parsed_metadata = json.loads(telemetry_data)
       validated_telemetry = ScanTelemetry(**parsed_metadata)
   except (json.JSONDecodeError, ValidationError) as e:
       raise HTTPException(status_code=400, detail=f"Malformed telemetry payload: {str(e)}")
   
   # Generate a unique cryptographic trace ID for distributed tracing
   trace_id = str(uuid.uuid4())
   
   # Await the reading of the file buffer into memory
   file_buffer = await image_payload.read()
   
   # Offload the high-latency storage operations to a background worker
   # This ensures the API returns a 202 Accepted immediately to the client
   background_tasks.add_task(
       persist_scan_data, 
       trace_id, 
       file_buffer, 
       validated_telemetry,
       image_payload.content_type
   )
   
   return {
       "status": "accepted", 
       "trace_id": trace_id, 
       "message": "Telemetry successfully queued for processing."
   }

Infrastructure and Database Strategy
A scalable machine learning data pipeline requires a bifurcated storage strategy. Attempting to store large binary objects (BLOBs) directly inside a relational database inevitably leads to severe performance degradation, table bloat, and excessive computing costs. Therefore, the architecture separates the storage of raw physical data from the logical metadata.
Storage Architecture Selection
The infrastructure utilizes a dual-database approach to optimize for both high-throughput writes and complex, structured analytical queries required for dataset curation.

Model Evaluation and Selection Paradigm
To address the highly specific challenge of recognizing degraded text in uncontrolled outdoor environments, the system requires an optical character recognition algorithm that fundamentally differs from legacy heuristic or purely convolutional approaches. The selection of the underlying model dictates the ultimate ceiling of the system's accuracy.
Analysis of Traditional OCR Architectures
Historically, OCR pipelines relied on heavily segmented, two-stage architectures, typically utilizing Convolutional Recurrent Neural Networks (CRNNs). Solutions like EasyOCR employ a Character-Region Awareness For Text (CRAFT) detector coupled with a CRNN and Connectionist Temporal Classification (CTC) loss for decoding. The CRAFT detector identifies spatial bounding boxes around characters, and the CRNN converts these visual features into text.
While computationally lightweight, these models process text fundamentally as a sequence of independent visual features. When faced with severe outdoor degradation—such as UV-faded text where an 'O' and a '0', or an 'I' and a '1' are visually indistinguishable—CRNN models lack the semantic understanding to infer the correct character based on the surrounding context.
Other modern approaches, such as LayoutLM and its derivatives, fuse spatial layout analysis with text recognition to parse visually rich documents. While exceptionally powerful for extracting structured data from invoices or complex multi-column forms, they introduce unnecessary computational overhead when the primary objective is extracting a singular, localized identification string (the EVSE ID) rather than parsing complex document topographies.
Recent advancements in large Vision-Language Models (VLMs), such as Florence-2 or Qwen 2.5 VL, offer robust zero-shot capabilities for understanding text within images. However, deploying multi-billion parameter models solely for reading a 20-character string is architecturally inefficient, resulting in excessively high inference latency and prohibitive cloud GPU computing costs.
The TrOCR Architecture Advantage
Microsoft’s TrOCR (Transformer-based Optical Character Recognition), accessible via the HuggingFace transformers ecosystem, is selected as the optimal foundational model for this service. TrOCR represents a paradigm shift by completely abandoning convolutional backbones in favor of a pure attention-based, encoder-decoder architecture.
The architecture consists of two deeply integrated components:
1. Vision Transformer (ViT) Encoder: The degraded image of the QR sticker is resized and divided into fixed-size patches (typically 16 \times 16 pixels). These patches are flattened, linearly embedded, and augmented with absolute positional embeddings before being processed by multi-head self-attention layers. This global attention mechanism allows the model to capture long-range visual dependencies, such as identifying the structural boundaries of an entire EVSE ID string despite localized glare or fading obscuring the middle characters.
2. Text Transformer (RoBERTa or BART) Decoder: The decoder operates autoregressively. It leverages the visual features extracted by the encoder, utilizing cross-attention, alongside previously generated text tokens to predict the next subword.
The mathematical and operational advantage of TrOCR is rooted in its objective function and pre-trained weights. The model optimizes the standard cross-entropy loss over the vocabulary sequence:
\mathcal{L}_{CE} = - \sum_{t=1}^{T} \log P(y_t \vert{} y_{<t}, \mathbf{x})
Where \mathbf{x} represents the visual embeddings and y_t is the text token at step t. Because the decoder is initialized from a pre-trained language model, it inherently possesses a statistical understanding of character sequences. In the context of electric mobility, if the model has been fine-tuned on DIN SPEC 91286 structures (+49[span_20](start_span)[span_20](end_span)[span_22](start_span)[span_22](end_span)*...), the language model decoder acts as an implicit statistical error-corrector. If the vision encoder outputs ambiguous features for a faded asterisk (*), the decoder's prior probability distribution will highly favor generating an * after a country code, effectively reconstructing text that is entirely invisible to traditional CRNN OCR engines. Empirical research consistently indicates that fine-tuning TrOCR via HuggingFace for outdoor and degraded text yields superior, cost-effective performance compared to legacy architectures.
Model Implementation and Inference Codebase
Implementing the selected TrOCR model requires careful configuration of the decoding parameters to prevent common generative AI issues, such as infinite token loops or hallucinated characters.
The implementation utilizes PyTorch and the HuggingFace transformers library to initialize the processor (handling both image normalization and text tokenization) and the generation model.
import torch
from transformers import TrOCRProcessor, VisionEncoderDecoderModel
from PIL import Image

class EVSEInferenceEngine:
   """
   Wraps the TrOCR model for high-performance EVSE ID extraction.
   """
   def __init__(self, model_checkpoint="microsoft/trocr-base-printed"):
       # The processor combines the ViT feature extractor and the RoBERTa tokenizer
       self.processor = TrOCRProcessor.from_pretrained(model_checkpoint)
       
       # Load the encoder-decoder model onto the optimal hardware accelerator
       self.device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
       self.model = VisionEncoderDecoderModel.from_pretrained(model_checkpoint).to(self.device)
       
       # Configure model generation parameters for deterministic, constrained decoding
       self.model.config.decoder_start_token_id = self.processor.tokenizer.cls_token_id
       self.model.config.pad_token_id = self.processor.tokenizer.pad_token_id
       self.model.config.vocab_size = self.model.config.decoder.vocab_size
       
       # EVSE IDs are strictly formatted and relatively short.
       # These constraints prevent the language model from hallucinating excess text.
       self.model.config.eos_token_id = self.processor.tokenizer.sep_token_id
       self.model.config.max_length = 40
       self.model.config.early_stopping = True
       self.model.config.no_repeat_ngram_size = 3
       
       # Use beam search rather than greedy decoding to improve accuracy on ambiguous characters
       self.model.config.num_beams = 5
       self.model.config.length_penalty = 1.0

   def extract_text(self, image_path: str) -> str:
       """
       Processes a degraded image and autoregressively generates the text string.
       """
       image = Image.open(image_path).convert("RGB")
       
       # Extract pixel values and normalize against the ViT pre-training distribution
       pixel_values = self.processor(image, return_tensors="pt").pixel_values.to(self.device)
       
       # Generate token IDs without calculating gradients (inference mode)
       with torch.no_grad():
           generated_ids = self.model.generate(pixel_values)
           
       # Decode the generated token IDs back into a human-readable string
       extracted_string = self.processor.batch_decode(generated_ids, skip_special_tokens=True)[0]
       
       return extracted_string.strip()

The use of Beam Search (num_beams = 5) is highly intentional. Instead of immediately selecting the single highest-probability token at each step (greedy decoding), the model maintains the top five most likely sequences in memory, evaluating the joint probability of the entire sequence. This is critical for EVSE ID extraction; a character that appears to be a '0' visually might mathematically resolve to an 'O' when the model evaluates the sequence probability of the subsequent country code tokens.
MLOps Pipeline: Continuous Training and Improvement
To continuously improve the scanning of QR stickers, the service must implement a closed-loop data engine. Stagnant models rapidly degrade in real-world efficacy. The system involves filtering incoming data, synthesizing missing failure modes, and executing automated fine-tuning runs.
Data Augmentation and Synthetic Degradation Simulation
While real-world failed scans provide the highest quality data, relying strictly on human-in-the-loop annotation for every failed API request is prohibitively expensive and slow. Therefore, the pipeline employs an advanced data augmentation strategy to artificially induce the precise conditions described in the problem statement—camera blur, dark exposures, and UV fading—onto existing, perfectly clear images of EVSE identifiers.
By utilizing the albumentations library, which provides high-performance image transformations, the system programmatically generates these failure states to rapidly expand the dataset size, vastly improving the model's robustness to visual noise.
import albumentations as A
import numpy as np
from PIL import Image

class DegradationSimulator:
   """
   Applies synthetic noise matching the distribution of outdoor EV charger degradation.
   """
   def __init__(self):
       self.pipeline = A.Compose([
           # Simulate "camera not getting a sharp image" (Focus & Motion Blur)
           A.OneOf([
               A.MotionBlur(blur_limit=15, p=0.6),
               A.GaussianBlur(blur_limit=(3, 11), p=0.4),
               A.Defocus(radius=(3, 8), alias_blur=(0.1, 0.5), p=0.4)
           ], p=0.5),
           
           # Simulate "too dark" or "too light" (Exposure clipping and Contrast loss)
           A.RandomBrightnessContrast(
               brightness_limit=(-0.5, 0.5), 
               contrast_limit=(-0.4, 0.4), 
               p=0.6
           ),
           
           # Simulate "the sticker is vading" (UV fading / washing out of black ink)
           A.ColorJitter(
               brightness=0.3, 
               contrast=0.1, 
               saturation=0.05, 
               hue=0.02, 
               p=0.5
           ),
           
           # Simulate physical hardware weathering (scratches and dirt)
           A.CoarseDropout(
               max_holes=10, 
               max_height=8, 
               max_width=8, 
               min_holes=2, 
               fill_value=255, 
               p=0.3
           ),
           
           # Simulate mobile camera sensor noise in low light environments
           A.GaussNoise(var_limit=(20.0, 60.0), p=0.4)
       ])

   def apply(self, image: Image.Image) -> Image.Image:
       image_array = np.array(image)
       augmented = self.pipeline(image=image_array)
       return Image.fromarray(augmented['image'])

Automated Fine-Tuning Integration
The training module utilizes the HuggingFace Seq2SeqTrainer. The MLOps pipeline routinely retrieves human-annotated ground-truth records from the PostgreSQL database, downloads the corresponding images from S3, applies the synthetic augmentations defined above, and fine-tunes the TrOCR model.
from transformers import Seq2SeqTrainer, Seq2SeqTrainingArguments, default_data_collator
from datasets import Dataset

class EVSETrainingPipeline:
   def __init__(self, model_engine: EVSEInferenceEngine):
       self.engine = model_engine

   def prepare_dataset(self, db_records, simulator: DegradationSimulator):
       """
       Transforms database records into tokenized HuggingFace Datasets.
       """
       def preprocess_function(examples):
           # Load images and apply synthetic degradation
           images = [Image.open(path).convert("RGB") for path in examples['image_path']]
           augmented_images = [simulator.apply(img) for img in images]
           
           # Encode visual features using the ViT processor
           pixel_values = self.engine.processor(augmented_images, return_tensors="pt").pixel_values
           
           # Tokenize the target textual EVSE IDs
           labels = self.engine.processor.tokenizer(
               examples['text'],
               padding="max_length",
               max_length=40,
               truncation=True
           ).input_ids
           
           # Mask padding tokens with -100 so they are ignored by the Cross-Entropy loss calculation
           labels = [
               [-100 if token == self.engine.processor.tokenizer.pad_token_id else token for token in label]
               for label in labels
           ]
           
           return {"pixel_values": pixel_values, "labels": labels}

       raw_dataset = Dataset.from_list(db_records)
       processed_dataset = raw_dataset.map(preprocess_function, batched=True, remove_columns=["image_path", "text"])
       return processed_dataset

   def execute_training_run(self, train_dataset, eval_dataset, output_dir="./models/trocr_evse"):
       training_args = Seq2SeqTrainingArguments(
           predict_with_generate=True,
           evaluation_strategy="steps",
           per_device_train_batch_size=16,
           per_device_eval_batch_size=16,
           fp16=torch.cuda.is_available(), # Utilize mixed precision to reduce VRAM usage
           output_dir=output_dir,
           logging_steps=50,
           save_steps=200,
           eval_steps=200,
           num_train_epochs=10,
           learning_rate=2e-5, # Low learning rate to prevent catastrophic forgetting of pre-trained weights
           weight_decay=0.01,
           load_best_model_at_end=True,
       )

       trainer = Seq2SeqTrainer(
           model=self.engine.model,
           tokenizer=self.engine.processor.feature_extractor,
           args=training_args,
           compute_metrics=self.compute_cer_metrics, # Defined in Section 7
           train_dataset=train_dataset,
           eval_dataset=eval_dataset,
           data_collator=default_data_collator,
       )
       
       trainer.train()
       self.engine.model.save_pretrained(f"{output_dir}/production_model")
       self.engine.processor.save_pretrained(f"{output_dir}/production_model")

The Active Learning Feedback Loop
The core value of this architecture lies in its autonomous feedback loop. When the model is deployed for inference within the primary backend system, the API validates the model's output confidence score and format compliance. If the resulting text does not match the strict regulatory syntax for EVSE IDs, the API flags the ScanEvent in the database as is_annotated = False.
These flagged records are automatically routed to an internal auditing dashboard where a human operator transcribes the severely faded sticker manually. Once human-annotated, the record is marked as ground-truth and triggers an asynchronous event that queues the image for the next scheduled fine-tuning job. This workflow guarantees that the model continuously learns precisely from its most difficult failure cases, systematically reducing the edge cases that trigger manual intervention.
Algorithmic and Domain-Specific Validation Strategy
Validation in this context cannot rely solely on generic machine learning loss metrics. EV charging identifiers function effectively as financial routing codes; a single character error prevents the user from initiating a session, or worse, inadvertently initiates a session on an adjacent hardware unit. Therefore, validation is divided into two distinct methodologies: algorithmic evaluation metrics and domain-specific format enforcement.
Algorithmic Evaluation Metrics (CER and WER)
During the Seq2SeqTrainer evaluation loop, the system calculates the Character Error Rate (CER). CER is the most critical metric for ID extraction, as EVSE IDs are contiguous, non-semantic strings lacking natural language whitespace.
CER is derived from the Levenshtein distance, which calculates the minimum number of single-character edits (insertions, deletions, substitutions) required to change the predicted string into the reference ground truth string.
CER = \frac{S + D + I}{N}
Where S is the number of character substitutions, D represents deletions, I represents insertions, and N is the total number of characters in the reference text. By tracking CER across epochs, the training engine guarantees that fine-tuning strictly reduces character-level hallucinations.
Regulatory and Domain-Specific Validation
Even with a theoretically perfect CER, the system must deterministically validate the generated string against international electric mobility standards before presenting it to the Tap Electric application routing logic. European charging infrastructure identifiers primarily adhere to two highly rigid formats.

import re

class EVSEFormatValidator:
   def __init__(self):
       # DIN SPEC 91286 / EVCO-ID Validation Pattern
       self.din_regex = re.compile(
           r"^(?:\+?[A-Z0-9]{2}[\*\-]?)?[A-Z0-9]{3}[\*\-]?[A-Z0-9\*]{1,30}$", 
           re.IGNORECASE
       )
       
       # ISO 15118-1 / EMA-ID Validation Pattern
       # The positive look ahead logic ensures compliance with standard deli[span_37](start_span)[span_37](end_span)miters
       self.iso_regex = re.compile(
           r"^[A-Z]{2}(\*?)[A-Z0-9]{3}(?:\2)[E][A-Z0-9][A-Z0-9\*]{0,30}$", 
           re.IGNORECASE
       )

   def validate_and_normalize(self, ocr_text: str) -> dict:
       """
       Cleans raw OCR output and validates against ISO/DIN mobility ID standards.
       """
       # Post-processing: Remove all whitespace often hallucinated by OCR models
       clean_text = re.sub(r"\s+", "", ocr_text).upper()
       
       # Heuristic correction: Models often confuse visual similarities
       # E.g., correcting an 'O' to a '0' if it occurs in a numeric-only field
       clean_text = clean_text.replace("O", "0") if clean_text.startswith("+") else clean_text
       
       is_din = bool(self.din_regex.match(clean_text))
       is_iso = bool(self.iso_regex.match(clean_text))
       
       return {
           "is_valid": is_din or is_iso,
           "detected_standard": "ISO_15118" if is_iso else ("DIN_91286" if is_din else "UNKNOWN"),
           "normalized_id": clean_text
       }

This dual-layer validation ensures that the ML model operates strictly within a deterministic envelope. If the TrOCR model extracts DE*1SE*E1234567910 (confusing the I in operator ISE for a 1), the regex validation engine can flag it for uncertainty. Furthermore, the system can apply dictionary-based heuristic corrections based on a known list of valid roaming operator IDs stored in the Tap Electric clearing house database.
Geospatial Cross-Validation
Finally, leveraging the latitude and longitude metadata ingested by the API, the system executes spatial validation via PostGIS. If the model predicts an EVSE ID belonging to operator TNM (The New Motion), but the mobile client's GPS coordinates are hundreds of kilometers away from any registered TNM asset, the system mathematically determines the OCR extraction is a localized hallucination and discards the result. The database executes a spatial intersection, accepting the predicted ID only if the client's location falls within an acceptable radius of the physical charger's registered coordinates.
Conclusion
The architecture detailed in this report transforms the static, single-point failure of optical QR code scanning into a resilient, continuously adapting machine learning ecosystem. By engineering a highly concurrent FastAPI ingestion layer, decoupling blob storage from relational PostGIS metadata, and deploying a state-of-the-art TrOCR model fine-tuned via the HuggingFace Seq2SeqTrainer, the platform can effectively recover failed charging sessions caused by uncontrollable environmental hardware degradation.
The specific architectural choice of TrOCR over legacy CRNN pipelines provides structural superiority when interpreting visually noisy inputs. The model's autoregressive text decoder contextually predicts ambiguous characters based on the innate sequential structure of the text rather than relying solely on corrupted visual features. By establishing an uncompromising validation protocol that anchors predictions against strict ISO 15118 and DIN SPEC 91286 regex standards combined with geospatial cross-referencing, the pipeline ensures that malformed data is never routed to the billing or session-initiation microservices.
Ultimately, this closed-loop automated pipeline creates a compounding proprietary data advantage. Every failed user scan provides the precise optical failure data required—authentic motion blur, challenging exposure profiles, and complex UV fading—to continuously fine-tune the model weights. Over successive training epochs, the service will asymptotically approach, and likely exceed, human-level text extraction capabilities directly from the mobile client edge, seamlessly routing EV drivers to the correct physical asset and dramatically reducing customer friction at the critical point of charge.
